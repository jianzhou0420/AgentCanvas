Define a Node

BaseCanvasNode — identity, typed ports, config fields, forward()

A node is one atomic function on the canvas: it takes typed inputs, does work, returns typed outputs. Everything on the canvas — tools, transformers, data sources, sinks — is a BaseCanvasNode subclass, and the class-level declarations you write here are the single source of truth for three surfaces at once: the canvas UI, the server-mode manifest, and the MCP projection. Write the declarations honestly and all three come for free. A node must belong to a NodeSet to be discoverable — that's the next tutorial.

1. The smallest useful node

File location: nodes live in their nodeset's module under workspace/nodesets/{role}/. This one node demonstrates every core concept — identity, a required and an optional port, a config field, and a forward():

from __future__ import annotations

from typing import Any, ClassVar

from app.components import BaseCanvasNode, NodeUIConfig, PortDef
from app.components.bases import ConfigField


class GreetNode(BaseCanvasNode):
    """Greet a name — the smallest useful node."""

    node_type = "my_tools__greet"      # {nodeset}__{node}, unique site-wide
    display_name = "Greet"
    description = "Prepend a greeting to the input name."
    category = "tool"                  # sidebar group
    icon = "Sparkles"                  # Lucide icon name

    input_ports: ClassVar[list] = [
        PortDef("name", "TEXT", "Who to greet"),
        PortDef("trigger", "BOOL", "Fire signal", optional=True),
    ]
    output_ports: ClassVar[list] = [
        PortDef("message", "TEXT", "The greeting"),
    ]

    ui_config: ClassVar[NodeUIConfig] = NodeUIConfig(
        color="sky",
        config_fields=[
            ConfigField("style", "select", label="Style", default="plain",
                        options=[{"value": "plain", "label": "Plain"},
                                 {"value": "loud", "label": "Loud"}]),
        ],
    )

    async def forward(self, inputs: dict, ctx: Any) -> dict:
        name = inputs.get("name", "")
        msg = f"Hello, {name}"
        if self.config.get("style", "plain") == "loud":
            msg = msg.upper() + "!"
        return {"message": msg}        # keys match output_ports exactly

3. Ports and wire types

Each PortDef(name, wire_type, description, optional=False) becomes an input/output handle on the canvas, a typed field in the server manifest, and a property in the MCP inputSchema. Ten inner wire types: IMAGE, DEPTH, ACTION, POSE, TEXT, BOOL, METRICS, OBSERVATION, STEP_RESULT, ANY. Consumer ports may wrap any type as LIST[T] for fan-in / multi-value (producers stay scalar; the executor wraps and concatenates in edge order).

  • optional is load-bearing. optional=False (the default) means the node won't fire until that port has data — and over MCP it lands in the schema's required list. Trigger-style inputs must be optional=True, or an MCP client's model is forced to invent a value for them.
  • Entry nodes: input_ports = [] — fires immediately when execution starts. Sink nodes: output_ports = [].
  • TEXT ports carrying structured content (JSON lists, base64) must state the exact format in the port description — the type system can only say string.

4. Config fields

Declare inline UI controls in NodeUIConfig(config_fields=[...]); read them in forward() via self.config.get("name", default). Over MCP they become optional tool arguments.

field_typeWidgetKey params / notes
"select"Dropdownoptions=[{"value","label"}], default — projects as a typo-proof enum
"slider"Range slidermin, max, step, default — projects as a bounded number
"toggle"Checkboxdefault (bool)
"text" / "textarea"Text inputplaceholder, default. The MCP type is inferred from the default — a numeric knob declared as text must carry a typed default (e.g. default=3, not None)
"label"Read-only textDisplay only; skipped by the MCP projection
"port_list"Dynamic port editorAdvanced — the _resolve_ports() pattern

Don't give a config field the same name as an input port — on the MCP surface the port wins and shadows the field.

5. forward() rules

  • Return a dict whose keys exactly match output_ports names; read inputs by port name.
  • No blocking I/O — await async clients (e.g. httpx.AsyncClient) or push heavy work through run_in_executor().
  • self._self_log("key", value) records voluntary interior logs (prompts, token counts) into the execution log.
  • ctx is a per-node state proxy for cross-fire state (loaded checkpoints, RNN hidden); module-level dicts work for state shared between nodes of one nodeset.
  • Batched inference (shared GPU forward across K workers) is opt-in via batched = True + batch_dim — see the server-mode capability page §7.

6. Being a good MCP tool

Any valid node projects to /mcp unchanged — but four declaration habits decide whether the projected tool is usable by a model (full mechanics: MCP Projection):

  1. Descriptions are the model's only manual — node description + port descriptions become the tool spec. Write them for a model operator.
  2. Required means required — audit every optional=False; the model must be able to supply all of them.
  3. Type your text-config defaults — the projection infers JSON types from them.
  4. Design outputs for context — IMAGE ports become native image blocks and ndarrays are stubbed to shape/dtype, but base64 bulk inside TEXT ports flows verbatim into the model's context. Keep TEXT outputs KB-scale, or accept the tool is graph-only and leave it off the --mcp-tools allowlist.

7. Checklist

  • node_type follows {nodeset}__{node}; display_name / description / category set
  • forward() returns keys matching output_ports; input names match input_ports
  • Wire types valid; trigger inputs optional=True; structured TEXT ports document their format
  • Config fields use select/slider/toggle where possible; text knobs carry typed defaults
  • from __future__ import annotations at file top; no blocking I/O in forward()
  • Outputs are context-sized (or the tool is consciously graph-only)
  • The node is returned from a BaseNodeSet.get_tools() — Define a NodeSet
