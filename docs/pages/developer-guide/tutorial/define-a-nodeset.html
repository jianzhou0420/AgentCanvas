Define a NodeSet

BaseNodeSet — placement, lifecycle, deployment contracts, three ways to load

A nodeset is the deployment unit: an atomic group of nodes that share initialization and shutdown — a loaded model, a simulator connection, a family of related tools. Every node must belong to one to be discoverable. The nodeset class is also where deployment is declared: which interpreter serves it (server_python), whether it's stateful under parallel eval (parallelism), and its MCP session policy (mcp_exclusive). Nodes themselves are the previous tutorial; the hosting machinery is Server Mode.

1. Placement and naming

  • Role directory first: every nodeset lives under one of workspace/nodesets/{env, method, policy, model, common, other}/. Deployment (own conda env) is not a directory concern — that's the server_python ClassVar.
  • Single file {role}/{name}.py by default; folder package {role}/{name}/__init__.py when there are sidecars (a simulator wrapper, vendored model code, presets) — sidecars live inside the folder with relative imports, never as _xxx.py siblings.
  • name equals the file/folder stem exactly, role prefix included: model/model_sam.py → name = "model_sam"; env/env_libero/__init__.py → name = "env_libero".
  • All node classes live in the entry module, above the NodeSet class; the module docstring carries the load line.

2. The skeleton

"""My Tools NodeSet — greeting utilities.

Load:  POST /api/components/nodesets/my_tools/load
"""

from __future__ import annotations

from typing import Any

from app.components import BaseNodeSet


# ... node classes above (see Define a Node) ...


class MyToolsNodeSet(BaseNodeSet):
    """Greeting utilities."""

    name = "my_tools"             # must equal the file/folder stem
    description = "Greeting utilities"

    # Deployment & eval contracts — all optional, defaults shown:
    # server_python = None        # interpreter for server mode (own conda env)
    # parallelism = "shared"      # "replicated" for stateful env nodesets
    # mcp_exclusive = None        # /mcp session policy; None derives from parallelism

    def get_tools(self) -> list:
        return [GreetNode()]      # instances, not classes

    async def initialize(self, **kwargs: Any) -> None:
        pass                      # heavyweight setup (models, connections)

    async def shutdown(self) -> None:
        pass                      # release GPU memory / close handles

3. Fields and contracts

FieldDefaultWhat it decides
namerequiredUnique identifier; must match the file/folder stem.
get_tools()requiredReturns node instances, not classes.
description""Shown in the NodeSet Manager UI — always set it.
server_pythonNoneInterpreter for server mode. Set when the nodeset needs its own conda env (pinned simulator, different torch); None = the backend's interpreter.
parallelism"shared"Eval-time contract (ADR-server-003). "shared": one instance, K callers may rendezvous through batched inference — right for stateless tools. "replicated": N tagged subprocesses, one per worker — required for stateful nodesets (env scene state, simulator handles).
mcp_exclusiveNone/mcp session policy. None derives from parallelism ("replicated" ⇒ one live MCP session, second initialize gets 409); pin True/False to override. See MCP Projection §5.
env_panelNoneA BaseEnvPanel subclass for runtime control (episode picker, dataset switcher) — lives inside the server subprocess.
default_per_step_budget_sec30.0Per-episode timeout knob for batch eval: episodes are clamped at max_steps × budget. Override when step latency genuinely diverges.
initialize() / shutdown()no-opHeavyweight setup / teardown. Eager-load what's always needed; lazy-load expensive maybe-unused resources in first forward().

4. Three ways to load it

The same class serves all three — no per-face code. Local for same-env tools; server mode for isolation (own interpreter, GPU, parallel workers); standalone auto_host when a coding agent or MCP client should call the tools directly:

# canvas, same process
curl -X POST http://127.0.0.1:8000/api/components/nodesets/my_tools/load

# canvas, own subprocess (server mode)
curl -X POST "http://127.0.0.1:8000/api/components/nodesets/my_tools/load?mode=server"

# standalone server — manifest protocol + native MCP face
python -m app.server.auto_host --file workspace/nodesets/common/my_tools.py \
    --class MyToolsNodeSet --port 9200
claude mcp add --transport http my-tools http://127.0.0.1:9200/mcp

In the standalone form the process serves GET /manifest, POST /call/{fn}, GET /health — and, when the mcp SDK (mcp==1.27.0, py≥3.10) is importable in its env, the native /mcp endpoint. Under batch eval, worker_count > 1 auto-routes "replicated" nodesets to server mode with N tagged subprocesses.

5. Where state lives

  • Per-node, cross-fire: the ctx proxy passed to forward() (loaded checkpoints, RNN hidden).
  • Shared between the set's nodes: module-level dicts (scratch pads, caches) — clean them up in shutdown().
  • Per-episode, partitionable: nodeset-owned state containers (declared via get_containers()), evictable per episode key.
  • If per-episode state cannot be partitioned (a simulator's scene), that is exactly the parallelism = "replicated" signal — and, derived from it, MCP session exclusivity.

6. Checklist

  • Exactly one BaseNodeSet subclass per nodeset; name matches the file/folder stem
  • All node node_type values start with {nodeset_name}__; get_tools() returns instances
  • Module docstring includes Load: POST /api/components/nodesets/{name}/load
  • from __future__ import annotations at file top
  • parallelism honest: "shared" for stateless tools, "replicated" for stateful envs (it now also drives mcp_exclusive)
  • shutdown() releases GPU memory and module-level state
  • Sidecars live inside the folder package, not as siblings
