看见 Agent 的思维链：为什么 SDK 只给「摘要」，怎么才能真正显示推理

我们用 Claude Agent SDK 驱动 VLN 时，存下来的 episode_*.jsonl（以及交互式 Claude Code CLI）里看不到「完整的思维链」。这不是我们漏存了 —— 而是 Claude 4+ 模型的原始思维链根本不会经由 API/SDK 返回。这篇把「拿不到什么」「已经存了什么」「怎么才能真正把推理显示出来」讲清楚，并用一次 habitat smoke 做了实证。

一句话：原始（token 级）思维链永远拿不到 —— SDK 最多给一段模型自己生成的摘要（display:"summarized"），甚至默认是空（"omitted"）。想真正「读到 agent 每一步为什么这么走」，唯一可靠的杠杆是让 agent 把推理写进可见的回复文本（ReAct 式叙述，落到 assistant_text）—— 这正是 wp prompt 已经在做、而 bare/full prompt 没做的事。加大 think_budget 只能让「摘要」更充实，改变不了「是摘要不是原文」这个上限。

1. 现象：outputs / CLI 里的「思维链」到底是什么

SDK harness（coding-agent/harnesses/claude_sdk.py）确实抓了 thinking —— 每个 ThinkingBlock 都会 emit 一条 thinking 事件（claude_sdk.py:169–171），落到两个地方：

  • episode_{i}.jsonl —— 规整过的 thinking 事件，字段 {chars, text}；
  • raw/episode_{i}.jsonl —— 原始 ThinkingBlock，字段只有 {thinking, signature}。

Monitor 前端也已经会渲染它（CodingAgentPage.tsx:59–64：有 text 就显示 text，没有就显示「thinking… (N chars)」）。所以问题不是「没存 / 没显示」，而是存下来的那段 thinking 本身就是一段被压扁的摘要，在 bare（adaptive）模式下往往只有一句话、甚至没有。

关键区分。「原始思维链（raw chain of thought）」＝模型内部逐 token 的真实推理；「摘要 thinking」＝一个更小的模型把那段推理压成的可读概述。你在 outputs / CLI 里看到的、能看到的，永远是后者。

2. 硬上限：原始思维链永远拿不到

对 Claude 4+ 模型（sonnet-5 / opus-4.8 / fable-5 等），Anthropic 官方文档写得很清楚：响应里永远不暴露原始 chain of thought。thinking 块的可见性由一个 display 字段控制，三种取值：

display返回的 thinking 文本说明
"omitted"空字符串4.7 / 4.8 / Sonnet 5 / Fable 5 的默认值 —— 有 thinking 块但文本为空
"summarized"一段可读摘要我们的 adapter 显式设了这个（claude_sdk.py:59–71）
——原始逐 token 推理任何 display 值都拿不到；这是 Anthropic 的刻意设计
display 只控制「可见性」；thinking 该发生照样发生、照样计费，但原始思维链在任何模型、任何设置下都不会被暴露。（Anthropic Thinking & Effort 文档）

换句话说：模型也许内部想了几千个 token（你也为这几千 token 付了费），但递回来的只是一句摘要 + 一个不透明的 signature。没有 flag、没有 beta、没有 SDK 选项能改变这一点。

3. Smoke 实证：8000 token 预算 → 50 字摘要

为了确认「不是我们配错了」，用真实的 claude_sdk.py adapter 跑了一次有界 habitat 单集（std_sdk_sonnet-5_bare，指向已在线的 env server :9300），并把 thinking 强制拉满：{"type":"enabled", "budget_tokens":8000, "display":"summarized"}。这段 config 在 session_inputs 事件里核对无误、确实下发了。

结果 —— 8 个 turn、14 个环境 step，只回来一个 thinking 块，50 个字符：

[smoke] captured 1 thinking blocks, 4 assistant_text blocks

===== thinking block 0  (50 chars) =====
Let me start by observing what we're working with.

[smoke] === raw ThinkingBlock 字段结构 ===
{
  "_type": "ThinkingBlock",
  "thinking": "Let me start by observing what we're working with.",
  "signature": "EoICCokBCA8YAipAneI6J+ThHgg2aKlqUy0e…"   // 不透明签名，非推理
}

8000 token 的思维预算 → 递回来一句 50 字符的摘要 + 一个签名。原始推理不在里面。raw 块里也没有 redacted_thinking —— 就是干净的「摘要 + 签名」。

顺带一个观察：原始 Messages API 对 sonnet-5 传 budget_tokens 会直接 400；但 Agent SDK / Claude Code CLI 接受了它并正常跑 —— CLI 在内部把 thinking config 做了自己的映射。这说明 CLI 的 thinking 处理是它自己一套，但摘要这个天花板不变。

4. 我们已经存了什么、存在哪、UI 显不显示

位置内容可见性
episode_{i}.jsonl · kind:"thinking"摘要文本 {chars,text}Monitor 已渲染
episode_{i}.jsonl · kind:"assistant_text"模型的可见回复文本（含它主动叙述的推理）Monitor 已渲染
raw/episode_{i}.jsonl原始 ThinkingBlock（thinking+signature）存档，非 UI

所以链路是通的。你「看不到完整思维链」的真实原因是两条：(a) bare 用 adaptive thinking，摘要稀疏；(b) 你想要的那个「完整原文」本就不存在（见 §2）。交互式 Claude Code CLI 同理 —— 它显示的也是同一段摘要。

5. 唯一能读到「完整推理」的杠杆：写进可见文本

既然 thinking 块必然是摘要，那想在每一步读到 agent「为什么这么走」的完整理由，正确做法是让它把推理当作普通回复文本输出 —— 这就是 ReAct 的「Thought:」叙述，落到 assistant_text，是模型的可见 output token，没有摘要、没有上限、逐字保留。

wp prompt 已经这么做了（coding-agent/prompts.py:96–100）：

Before every goto() or stop(), reason out loud in one or two sentences … Do this thinking as visible text, then call the tool.

而 BARE_SYSTEM_PROMPT / SYSTEM_PROMPT（prompts.py:52–76）没有这条规则。差距立现：

episodethinking 块单块示例长度assistant_text
wp（sonnet-5，含叙述指令，整集）24~248 字，实质推理19
bare smoke（sonnet-5，无叙述指令，8 turn 有界）150 字4

注意 wp 的 think_budget 更小（4000 vs 8000）却拿到远多得多的可读推理 —— 决定性因素是「叫模型把推理说出来」，不是思维预算大小。（bare smoke 被我截到 8 turn，块数差有一部分来自集长，但单块 50 vs 248 字这个「实质度」差异才是要点。）

6. 次要杠杆：把「摘要」喂厚一点

如果你只是想让 thinking 块本身别那么稀疏，可以强制 enabled thinking + 一个预算（wp 就是这么干的，WP_THINK_BUDGET=4000）。走 --nonstd --set 即可：

python coding-agent/stdrun.py run std_sdk_sonnet-5_bare \
  --servers http://127.0.0.1:9300 --episodes 0 \
  --nonstd --run-name smoke_cot --set think_budget=8000

这让摘要比 adaptive 的一句话更充实，但 —— 再强调一次 —— 它仍然是摘要。

7. 落地建议

  1. 接受原始思维链拿不到 —— SDK 顶多给摘要（§2、§3 已证）。别再找「显示完整 CoT」的开关，没有。
  2. 想逐步读推理 → 给 bare/full prompt 加一条叙述规则（照抄 wp 的 prompts.py:96–100）：「每次 step() 前，用一两句话把你现在在执行指令的哪一段、为什么这么走，作为可见文本写出来。」它落到 assistant_text，逐字、无损、Monitor 已渲染。（注意：这会改动 prompt 冻结，属于 std-v3；做对照实验时要单列，别混进现有 board。）
  3. 可选：强制 enabled+think_budget 让 thinking 摘要更实（§6），作为次要补充。
  4. 看的时候看对文件：assistant_text（叙述推理）+ thinking（摘要）两类事件都在 episode_{i}.jsonl 里，Monitor 一并显示。

8. 附录：相关文件与复现

  • thinking 配置coding-agent/harnesses/claude_sdk.py:59–71（_thinking_config）
  • thinking 抓取coding-agent/harnesses/claude_sdk.py:169–171
  • 叙述指令coding-agent/prompts.py:96–100（仅 wp）；bare/full 在 prompts.py:52–76（无）
  • 思维预算coding-agent/cells.py:81（WP_THINK_BUDGET=4000）
  • UI 渲染agentcanvas/frontend/src/pages/coding/CodingAgentPage.tsx:59–64

Smoke 复现（env server 需先在线，例如 :9300）：直接用真实 adapter 跑一集，把 think_budget 拉满、display 保持 summarized，dump 所有 thinking 块 —— 观察到的就是「8000 预算 → 50 字符摘要 + signature」。
