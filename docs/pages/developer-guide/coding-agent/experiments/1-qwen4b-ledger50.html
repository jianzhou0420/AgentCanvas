Qwen3.5-4B × ledger-nav × rand100 前 50 集 — 实验报告

开源 4B 小模型第一次成批跑通 coding-agent VLN 管线：SR 0.12（n=50）、$0 API 成本、3.2 小时单卡完成、约 3,800 轮工具调用 0 次格式失败。本文是数据记录 + 有效性声明，先读数字再下判断。

这是 CAN 计划的第一个成批开源小模型数据点：beta-react-harness（mini-swe-agent 2.4.5）驱动 Qwen3.5-4B（Q8_0，本地 ollama），挂 ledger-nav skill，跑 R2R-CE rand100 前 50 集——与 beta-coding-agent 和 beta-react-harness/REPORT.md 的全部 n=50 基线逐集同题可比。运行是我（Claude）在本机全自动执行的：起服务、发批次、监视、评测、审计，全程无人值守。工件在 outputs/beta-react-harness/qwen4b_ledger50_w10/。

5. 失败结构：4B 的病和 Claude 不一样

桶（按停点距目标，互斥）n占比episodes
成功（<3 m）612%1, 12, 25, 26, 37, 47
near-miss（3–5 m）612%7, 30, 31, 41, 45, 48
中距失败（5–10 m）1734%—
远距迷走（>10 m）2142%其中 ep46 走到 19.4 m
  • 主导失败是「走丢」不是「停错」：42% 的集停点离目标 10 m 开外，且往往伴随大量步数（ep5 走 341 步到 14.7 m、ep10 走 485 步到 9.5 m）——模型在错误方向上持续勤奋。这与 Claude 系的典型失败（near-miss 或过早 STOP）结构不同：4B 缺的不是纪律而是指令-场景接地。
  • 纪律部分确实被 skill 撑住了：stop_rate 0.88（6 次不停里 3 次是把 500 步预算走穿）；成功的 6 集全部干净利落（nDTW 0.77–0.84，SPL 最高 0.94）。ledger 给了 4B「赢法」，没给它「不输法」。
  • 方差实录（同一 ep0 三次采样）：昨早 window-5/32K 成功（dtg 0.59）→ 本批前身 window-5/65K 失败 → 本批 window-10/65K 失败（8.21）。temp=1.0 下单集结果是抽样，50 集聚合才有意义——这也是把上午 ep0 的成功故事降级为「幸运抽样」的诚实修正。

7. 有效性声明（引用本表前必读）

  • 采样口径：temp=1.0（模型默认，harness 未传参）单次采样，无置信区间。§5 的 ep0 三连已示范单集方差之大。正式对照需钉 temp=0 或 ≥3 种子。
  • 量化口径：Q8_0 近无损，但论文口径应为 bf16（vLLM 栈）；ollama+Q8 是本批的服务栈，数字标注应带此后缀。
  • 上下文口径：image-window 10，而 REPORT 的全部 Claude 批次是 window 0（全帧保留）——图像可见性对 4B 更严苛。文本历史两边都是全量线性。
  • skill × mini 是首次组合：Claude 的 +ledger 数字全部来自 SDK harness，严格讲「4B+ledger vs sonnet 无 skill」不是单变量对比。缺的对照臂：4B 无 skill 50 集（预计 ~2.5 h、$0，最值得补的一跑）。
  • turns 口径：max-turns 100 与 mini Claude 批一致；与 SDK 批（80）有已记录的差异。

8. 下一步（按信息量/成本排序）

  1. 4B 无 skill 50 集（~2.5 h，$0）——补上 skill 单变量对照，直接回答「ledger 给 4B 带来几个点」。
  2. 9B 同配置 50 集——规模阶梯的关键中间点，H7（vs AgenticNav 27B=0.35）的命运判据；权重已在 HF 缓存。
  3. temp=0 重跑本配置——消掉方差口径问题，同时验证 24 次解析噎住是否归零。
  4. 失败标注：per-episode 按 NavHarness 六类归因（本批原始轨迹 raw/ 全量在盘，可直接标）。
  5. 正式测量迁移 vLLM bf16（--gpu-memory-utilization 0.65），ollama 退回调试/图臂角色。
