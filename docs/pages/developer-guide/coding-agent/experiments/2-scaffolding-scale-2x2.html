脚手架 × 规模：Qwen3.5 导航的 2×2 消融

这是 CAN 计划的第一个完整因子设计：qwen3.5-{4b, 9b} × {bare, nav} 四个 std cell，每个 rand100 前 50 集，全部在同一套冻结协议下、$0 API 成本、seed=42 逐字节可复现。它给出两个结论：一个阳性、显著、可发表的交互效应——coding-agent 脚手架与模型规模互补，单独任何一个都不动导航能力；以及一堵不随任何旋钮移动的墙——「停止」决策，它决定了成功率为什么上不去。

一句话：在这套 harness 上，从 4B 到 9B、从裸 prompt 到全脚手架，规模买到的是「找到目标」（OSR，走进目标 3 米内），不是「承认找到了」（SR，成功宣告停止）。导航能力在「规模 × 脚手架」都齐备时显著提升；停止决策在四格里全部卡在 33–50% 的转化率，不随规模、脚手架、分辨率、回合预算、采样中的任何一个改善。

1. TL;DR

四个 cell 各 50 集，同一组 episode，配对 McNemar 检验。核心指标是 OSR（oracle success rate，轨迹曾经进入目标 3 米内）和 SR（success rate，在目标处发出 STOP）。

  • OSR 上有一个教科书式的交互效应。 光有 skill（4B 上加 ledger-nav）：p=1.0，无效。光有规模（bare 条件下 4B→9B）：p=1.0，无效。两者都有（9B+skill）：从两个独立方向各自 p=0.0215 显著。OSR 三格持平（0.16 / 0.18 / 0.18），只有 9b_nav 一格翻倍到 0.34。
  • SR 在任何一格都没有显著变化。 因为「走到目标之后能不能停对」的转化率被焊死在 33–50%，四个 cell、两个规模、两种条件都一样。
  • 分辨率、回合预算、采样惩罚——逐一排除。 5 倍像素（224→512）、回合 150→100、把重复惩罚全部归零，都确实改变了行为（动作批量、路程、停止率都变了），但 SR / OSR 纹丝不动。
  • 唯一没被撼动过的是 STOP 决策本身。 它是成功率的真正瓶颈，也是 CAN 下一步该攻的地方。

2. 协议与完全可复现口径

这套协议的每一层——包括三个平时没人钉的服务层默认值——都是从服务器读回并断言的，不是 harness 声称的。凡是钉不住的，adapter 就拒绝运行，而不是静默降级。

关于采样的两个坑（写方法章节必须交代）：
  • 确定性来自 seed，不是温度。 temp=1.0 配固定 seed 即可逐字节复现；stock ollama 不传 seed，所以本日之前每一集都是一张随机彩票。
  • litellm 的 ollama 路由静默丢弃 presence_penalty（drop_params=True），在客户端设它等于没设。所以采样只能烤进 Modelfile，再从 /api/show 读回验证。repeat_penalty 是乘法（logit/penalty），中性值是 1.0 不是 0——设 0 会除以零、强制重复循环。

4. 交互效应：脚手架与规模互补

四组配对 McNemar，都是同一组 50 集内的配对比较（A 独有 / B 独有 是两者结果不一致的集数，p 是精确双侧检验）。

对比变量指标A 独有B 独有p
4b_bare → 4b_nav加 skill（4B）OSR451.0000—
4b_bare → 9b_bare加规模（bare）OSR451.0000—
9b_bare → 9b_nav加 skill（9B）OSR190.0215✓ 显著
4b_nav → 9b_nav加规模（nav）OSR190.0215✓ 显著
这是一个干净的交互（interaction），不是两个主效应。 加 skill 在 4B 上无效（p=1.0），加规模在 bare 上无效（p=1.0）；只有当两者同时具备，OSR 才从两个独立方向各自显著跳升。翻译成机制：4B 拿到 skill，只学会了「走得多」（环境动作 65→322），学不会「走得对」（OSR 0.16→0.18）；9B 不给 skill，也只是走得稍远（65→108）。只有 9B 拿到 skill，才把移动能力转化成真正朝目标的导航。

这直接反驳了本项目最早的一个单集轶事——4B 挂上 ledger-nav 后第 0 集从失败变成 SR 1.0，当时被当作「coding-agent 纪律拯救小模型」的证据。n=50 的配对检验说：那是运气。 在 4B 上，skill 买到的是移动，不是成功。

推论：coding-agent 的脚手架存在一个「接得住」的最小能力门槛。 这比「skill 对小模型有用」更有意思，也解释了一整天里所有看似矛盾的观测——为什么 4B 走了 5 倍的路却只多摸到 1 次目标。

5. 停止之墙：为什么 SR 不动

把 SR 也做配对检验，会发现同一个 n=50 的设计，有功效检出 OSR 的效应，却检不出 SR 的效应：

对比指标A 独有B 独有p
4b_nav → 9b_nav（加规模）OSR190.0215 ✓
4b_nav → 9b_nav（加规模）SR360.5078
9b_bare → 9b_nav（加 skill）OSR190.0215 ✓
9b_bare → 9b_nav（加 skill）SR260.2891

这不是「样本不够」。这是说：规模确实、显著地让模型更会找路，但这份收益在「停下」那一步被丢光了。 转化率给出了丢在哪：

  • 4B：走到目标的 9 集里成功 4 集 = 44%
  • 9B：走到目标的 17 集里成功 7 集 = 41%

规模把机会翻了一倍（OSR 0.18→0.34），转化率一步没动。失败分类也吻合——「到过 3m 内却没停对」这一桶，从 4b_nav 的 5/50 涨到 9b_nav 的 10/50，正好和 OSR 同比例翻倍。9B 把新赢来的机会，原封不动地按同样比例浪费掉了。

6. 排除项：三个旋钮都不动 SR

今天最贵的负结果来自和归档跑的对照。把 4b_nav 从旧协议（224px / 150 回合 / pp=0.5）换到新协议（512px / 100 回合 / pp=0），三个正交旋钮一起拧：

4b_navSROSRnDTW动作批量stop_rate
旧：224px / 150 回合 / pp0.50.080.180.302.50.68
新：512px / 100 回合 / pp00.080.180.323.40.54
SR 和 OSR 精确到小数点后两位不变——而干预是真实生效的。 动作批量从 2.5 涨到 3.4（+36%），stop_rate 从 0.68 掉到 0.54，模型行为确实变了，只是成功率不变。所以这不是「什么都没改」，而是「改了行为、没改结果」。感知精度、回合预算、采样惩罚——三个都被排除。

关于分辨率值得多说一句，因为直觉上它「应该」有用。R2R 指令常常要求识别一个精确地标（如「停在吧台转角」），而在 224px 下这个地标基本糊成一团：

直觉是对的——224px 确实看不清该停在哪。但实验说：把它换成 512px，SR 还是不动。 说明「看不清」不是当前的绑定约束；就算把地标看清了，模型也不会因此就知道该停。瓶颈在更下游。

两个失败模式随「加脚手架」而互换：bare 的主导失败是撞回合上限（32、36 / 50，因为动作批量只有 1.5–2.4，100 回合换不来足够动作），nav 把它换成了烧光动作预算不肯停（13、17 / 50）。skill 完美地修好了「走不动」，一点也没修好「走对/停对」。

9. 有效性声明与限制（引用本表前必读）

  • 单 seed。 每个 cell 是 seed=42 的一个样本。McNemar 是跨 episode 的配对，不是跨 seed 的。SR≈0.1 时区分 0.08 与 0.14 需要每臂 200+ 集——所以本报告只声称 OSR 上的效应（效应量大到 n=50 能测出），不声称 SR 上的规模效应（p=0.51，未达显著）。
  • bare ≠「裸模型能力」。 bare cell 有 64–75% 的集撞在 100 回合上限（动作批量 1.5–2.4）。所以 bare 测的是「没有脚手架就被回合预算饿死」，不是「裸导航能力」。要测后者，bare 需要一个动作对齐的回合预算（约 270 回合）。
  • 「排除分辨率」的对照同时动了三样。 §6 那组严格讲是「512/100/pp0 与 224/150/pp0.5 结果相同」，即这三者一起不动 SR；单独隔离 512 的贡献需要一个 512/150/pp0 的干净臂。
  • bare vs nav 差 6 样东西。 nav 相对 bare 同时变了：prompt 文本、clearance 读数、look_around 工具、回合广播、STOP 门控、ledger-nav skill。所以 §4 的交互效应归因到「整套脚手架」，不能拆分到「是机制还是 skill」——那需要第三条 mech 臂（full 机制但无 skill）。
  • 方法自省。 得到这些结论的过程里，我至少三次把小样本观测（n=1 或 n=10）过度解读成机制，全部被更大样本推翻（「4B 永远单动作」被 nav 分布推翻；「presence_penalty 砍半批量」被 6 帧扫描推翻；「512 让 SR==OSR」被 20 集推翻）。本报告只保留了扛住 n=50 的结论。

10. 下一步（按信息量排序）

  1. 攻停止之墙。 这是唯一没被撼动过的东西，也是 SR 上不去的唯一原因。ledger 的 verify-before-STOP 纪律在 opus 上把「从不停」从 14/50 打到 0/50，但没传导到小模型——为什么？一个小模型真能执行的停止协议，是最高价值的干预。
  2. 补 mech 臂（full 机制但无 skill），把 §4 的交互效应从「整套脚手架」拆分到机制 vs skill。
  3. 动作对齐的 bare（约 270 回合），测出真正的「裸导航能力」，而不是「被回合饿死」。
  4. 多 seed，把 SR 的方差量化到底，判断规模在 SR 上到底有没有效应。
