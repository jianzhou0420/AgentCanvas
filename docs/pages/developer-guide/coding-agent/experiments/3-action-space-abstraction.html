抽象层级决定具身：动作空间、模型规模与脚手架的三方证据

把同一个开源小模型接到不同抽象层级的动作空间上，成功率能差 5 倍。这是 CAN 计划横跨三条实验线——qwen4b ledger 50 集、脚手架×规模 2×2、以及新做的 waypoint 动作空间——汇总出的一个结论：具身能力主要由「模型在哪一层介入」决定，其次才是模型本身，脚手架（skill）排在最后。这与 Anthropic 官方研究 Claude Plays Robotics 的核心论点一致——「能力取决于模型如何被接到机器人上」。

一句话：小模型（qwen3.5-4b）在低层 step 动作（前进 0.25m / 转 15°）上近乎废掉（SR 0.08）；换到高层 waypoint 动作（在预测器给的候选点里选一个编号）上立刻变得能用（SR 0.42，n=50）。这一步抬升,单靠「加大模型」或「加脚手架」在 step 空间里都做不到。抽象层级是主变量,模型规模是次变量,skill 是修饰量——而且 skill 只帮「中间那一档」模型,两头都无效。

1. TL;DR

  • 抽象层级把小模型救活。 qwen3.5-4b：step 空间 SR 0.08 → waypoint 空间 SR 0.42（n=50，同一 rand100 50 集，$0，seed=42 可复现）。OSR（走进目标 3m 内）从 0.16 抬到 0.52,3 倍。
  • 这件事 scale 和 skill 都做不到。 在 step 空间里,4B→9B、裸 prompt→全脚手架,SR 全部卡在 0.06–0.14（见 2×2 报告）。waypoint 空间里一个 4B 模型（0.42）就超过了 step 空间里加了规模又加了脚手架的 9B（0.14）。
  • waypoint 同时松开了两道锁。 「到达」（OSR 0.16→0.52）和「停对」（转化率 50%→81%）一起改善——2×2 报告里那堵焊死在 33–50% 的「停止之墙」,是 step 动作空间特有的,换动作空间就塌了。
  • skill 是一条倒 U。 太弱的模型跑不动脚手架(4B:step +0.00 / wp +0.02,p=1.0),太强的模型不需要脚手架(opus:step 0.48→0.50)。只有中间那一档吃到红利(9B:step 0.06→0.14;sonnet:wp 0.35→0.58*)。模型越强,手写 skill 越不重要。
  • 结论。 具身要让模型从越来越高的层面介入——把低层控制交给预训练控制器/工具,模型只做高层决策。趋势是 workflow(确定性高层结构)+ ReAct(在环适应),而不是给模型堆手写脚手架。

* sonnet wp 的两个条件 n 不等(20 vs 50)、非配对,是提示性证据而非定论——见 §7 有效性。

4. 为什么:动作空间买到「到达」,也松开「停止之墙」

SR 是「到达 × 停对」两件独立的事的乘积。拆开看,waypoint 在两条轴上都赢:

  • 到达(OSR): qwen-4b 从 0.16(step)→ 0.52(wp)。step 空间里 qwen 被回合饿死、根本走不到目标区;waypoint 一步一个真实位移,走到的概率翻 3 倍。
  • 停对(转化率 = SR/OSR): 从 ~50%(step)→ ~81%(wp)。2×2 报告发现停止转化率被焊死在 33–50%、不随规模/脚手架/分辨率/回合/采样移动——但那是在 step 空间里。换成「在 ≤5 个候选点里选一个 / 或停」这种离散决策,小模型的停止立刻好起来。
最锋利的一句:waypoint 空间里的 4B(OSR 0.52 / 转化 81%),在两条轴上都超过了 step 空间里那个唯一「显著移动」的格子 9b_nav(OSR 0.34 / 转化 41%)。换动作空间,给一个更小的模型,做到了加规模又加脚手架都没做到的事。

5. skill 的倒 U:脚手架只帮中间那一档

把「加 skill 带来的 SR 变化」按模型能力排开,是一条倒 U——两头无效,中间有用。

模型 / 空间bare+skillΔ SR判定
qwen4b · step0.080.08+0.00无效(跑不动)
qwen4b · waypoint0.400.42+0.02无效 · McNemar p=1.0
qwen9b · step0.060.14+0.08有效(2×2 的交互效应)
sonnet5 · waypoint0.35*0.58+0.23*提示有效 * 非配对
opus4.8 · step0.480.50+0.02无效(不需要)

机制在 wp 报告里直接看到过:qwen-4b 在 waypoint 上跑得挺好,但它的 <think> 里完全没有执行 skill 要求的那套账本(位姿、已访问点、best-stop 全为 0 次)——它读不动那套记账纪律,所以 skill 对它既不帮也不害,SR 0.40 vs 0.42、p=1.0。另一头,opus 本来就会导航,ledger 只值 +0.02。脚手架的价值随模型能力先升后降:太弱执行不了,太强不需要。

对 CAN 的含义:模型越强,手写 skill 越不重要。随着开源模型变强,与其给它堆越来越精巧的 prompt 脚手架,不如把力气花在动作空间的抽象层级和agent flow 的结构上。这和 Anthropic 报告里「额外推理对多数结果影响很小、有时反而更差」是同一个方向——瓶颈不在多喂 token / 多写 prompt。

6. 交互形式与记忆:诚实的一节

关于「多轮全历史 vs 单轮 API + 历史总结哪个好」,必须把话说准,因为这是本项目没有直接做消融的一块:

  • 我们两套 harness——SDK(闭源,原生多轮 agentic,回合间 thinking)和 mini(开源 ~500 行 ReAct,每回合一次 litellm.completion)——都用完整线性历史,没有任何一套做「历史总结/截断」。所以「全历史 vs 总结」这个对比,我们并未测。
  • 能说的是循环形式:同模型下 SDK 的富 agentic 循环比裸 ReAct 略好(opus:sdk-bare 0.48 vs mini 0.42),但差距不大,且被 thinking/原生 tool-use 等因素混淆,不能单独归给「多轮」。
  • 更要紧的是:Anthropic 报告在记忆这一维上给的是相反的证据。他们发现模型「更依赖近期,而非对早先一切的累积理解」,而且「truncating historical context often improves performance」(截断历史往往提升表现)。所以「全历史一定更好」不成立——至少不是无条件成立。
所以本报告不主张「全历史优于历史总结」。诚实的表述是:决定成败的是循环的形式(能不能多轮、能不能看到上一步结果并在环调整),而不是喂进去的历史越多越好。Anthropic 说的「代际进步来自更善于在看到先前结果后调整策略」,支持的是 ReAct 式在环适应,不是「把所有历史都塞进去」。这一维要下结论,得专门做一个「全历史 vs 窗口/总结」的消融——列进 §8 下一步。

7. 和 Anthropic《Claude Plays Robotics》对齐的部分

我们的数据和 Anthropic 官方报告在抽象层级这条主线上高度一致(原文引用):

  • 「how capable they are depends heavily on how they are connected to the robot」——能力主要由「接到机器人的方式」决定。⟵ 我们:同一个 4B,动作空间从 step 换到 waypoint,SR 0.08→0.42。
  • 「a model does not need to drive joints itself to act capably」——模型不必自己驱动关节也能干活;监督一个预训练控制器就行。⟵ 我们:waypoint 的低层运动交给深度预测器,模型只选点,「一次一动作」的短板消失。
  • 「Models are improving at robotics, but unevenly」——高抽象接口上稳定进步,低层参差。⟵ 我们:step 空间里连 9B+脚手架都只有 0.14;抬到 waypoint 才连续可用。
  • 他们没有 VLA 策略时成功率掉到 0–5.5%;我们没有 waypoint 时 4B 只有 8%。两边都是同一个故事:没有合适的高层接口,LLM 的具身能力接近于零。

8. 结论:把模型抬到更高层 —— workflow + ReAct

三条实验线拼出的设计原则:

  1. 抽象层级是第一杠杆。 给小模型一个高层动作空间(waypoint / 预训练控制器 / 工具),比换更大的模型或写更精巧的 prompt 都更划算。具身要让模型从越来越高的层面介入。
  2. 脚手架随能力退场。 skill 只帮中间档;前沿模型不需要,极弱模型执行不了。手写脚手架不是长期方向。
  3. 好的 agent flow = workflow + ReAct。 用确定性的高层结构(workflow / 预训练控制器)托住低层,让模型在这套结构里做高层决策并在环适应(ReAct:看到上一步结果就改)。这正好落在 Anthropic 的两个发现之间——「监督预训练控制器」+「代际进步来自看到结果后修正策略」。
一句话收束:让模型少驱动关节、多做决策;少背历史、多在环调整;少喂手写脚手架、多给它高层原语。CAN 的下一步就是沿这条线——把 waypoint 这类高层动作空间做扎实,并让开源模型在 workflow+ReAct 的结构里编排它。

9. 有效性与边界

这份报告是汇总性的,证据强度不均,必须标清楚:

  • 最强的一条(抽象层级救活小模型)靠得住:qwen-4b step 0.08 → wp 0.42,n=50,效应量巨大,方向不可能被回合预算差异翻转(回合更多只会更好)。
  • 跨模型 SR 有协议混淆。 闭源 step 基线是 80 回合 / 224px 的归档跑,qwen step 是 100 回合 / 512px。所以「fable 0.64 > qwen 0.08」里既有模型差也有协议差——用来说明层级没问题,用来精确排模型座次要小心。
  • skill 倒 U 是跨空间拼出来的,含小样本。 sonnet·wp 两条件 n=20 vs 50、非配对(+0.23 带星);9B·step 的 +0.08 来自 2×2。倒 U 的形状可信,单点数值别当定论。
  • 「全历史」这一维我们没测,且 Anthropic 证据反向——见 §6,不下结论。
  • 9B×waypoint 没跑(本轮按需搁置)。它是最该补的一格:skill 在 waypoint 空间到了能执行账本的规模会不会终于生效?这决定倒 U 的右半段在高层空间长什么样。
  • waypoint 的低层运动质量依赖 SmartWay 深度预测器;它的候选点误差会给所有 wp 数字设一个共同上限(OSR 天花板 ~0.5–0.7)。
