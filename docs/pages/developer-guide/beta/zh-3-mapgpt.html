用普通大模型跑 MapGPT（中文）

标准图式流程：MapGPT 图 + MatterSim 环境 + 任意 OpenAI 兼容 LLM。

与上一篇的 coding-agent 路线相反，这是 AgentCanvas 的正统玩法：MapGPT（ACL 2024，zero-shot VLN 的 map-guided prompting）被移植成一张类型化的图，方法逻辑、模拟器、LLM 三者解耦 —— LLM 只是图里一个 llmCall 节点，指向哪个"普通大模型"完全由 profile 配置决定。系列文档：仓库概览 · 跑 Beta Agent · 本篇 · Agent vs Coding Agent。方法细节的英文正式页：MapGPT nodeset。

1. 三块拼图

拼图位置说明
图workspace/graphs/vln/verified/mapgpt_mp3d.json已验证图 "MapGPT-MP3D"：22 节点 / 49 边，step_budget: 50；状态容器 graph_state 存 topo_map / history / planning。eval API 里的图名即文件名词干 mapgpt_mp3d。
方法 nodesetworkspace/nodesets/method/mapgpt.py8 个 mapgpt__* 节点：observe → update_map → build_options → render_prompt → parse_action → update_history（+ image_budget、system_prompt）。纯推理，不碰模拟器、无模型权重。
环境 nodesetworkspace/nodesets/env/env_mp3d/MatterSim 离散全景 MP3D 图环境，waypoint 动作空间：env_mp3d__reset / observe_navigable / observe_panorama / step_waypoint / evaluate。以 server mode 跑在 ac-mp3d 环境（解释器覆写：MP3D_PYTHON）。

每步循环：环境给全景 + 可导航候选 → update_map 更新文本拓扑地图 → render_prompt 织出带地图/历史/上轮规划的 prompt → planner_llm（LLM 节点）出决策 → parse_action 解析出 waypoint → step_waypoint 落步，直到 STOP 或步数预算耗尽。

2. "普通大模型"怎么接：profile 体系

图里的 LLM 节点 planner_llm（类型 llmCall，多模态）只存一个 profile 名：

"planner_llm": { "profile": "gpt-5-mini", "temperature": 1,
                 "max_tokens": 6000, "mode": "single_turn", … }
  • profile → 供应商/模型：profile 定义在 agentcanvas/backend/profiles.json（可用 AGENTCANVAS_PROFILES_FILE 换文件），形如 { name, provider, model, base_url }，永不存 key。
  • provider → 端点：provider 是 app/llm/providers.py 里 PROVIDER_REGISTRY 的键，自带 base_url 和标准 key 环境变量。全是 OpenAI 兼容口径：openai（OPENAI_API_KEY）、openrouter、deepseek、together、moonshot、mistral、xai、nvidia，以及自托管 vllm / sglang（localhost:8000/v1、:30000/v1）和本地 ollama（免 key）。profile 里的 base_url 可覆写成任意自定义端点。
  • key 的解析顺序：先查 Settings UI 写的密钥库 ~/.agentcanvas/.keys，再查 provider 对应的环境变量。两处都没有 → profile 不可用，节点落入 mock 模式（跑不出真结果，但不报错 —— 排查时注意）。

换模型的两条路：(a) 保持图不动，在 profiles.json 里定义/修改名为 gpt-5-mini 的 profile 并导出对应 key；(b) 改图 JSON 里 planner_llm.config.profile 指向你新建的 profile（比如指向 vllm 上的 Qwen）。

temperature 的坑 gpt-5 家族要求 temperature 恰为 1.0（否则 litellm 抛 UnsupportedParamsError）；换非 gpt-5 模型时可以自由调。另外 AAS 搜索约束里"锁定 gpt-5-mini + temp 1.0"只是搜索循环的控制变量要求，手动/评测运行不受限。

3. 数据与环境准备

  • MatterSim 环境：bash scripts/install/install_ac_mp3d.sh（建 ac-mp3d conda 环境并编译 MatterSim）。
  • MP3D 场景 skybox：python3 scripts/data/fetch_scans_mp3d.py（90 个 scan，需接受 Matterport 使用条款，--accept-tos 跳过交互）→ 再跑 scripts/data/gen_skybox_rgb_mp3d.sh 生成 MatterSim 读取的 RGB skybox 瓦片（要深度再加 gen_skybox_depth_mp3d.py）。
  • 连通图：随 third_party/Matterport3DSimulator/connectivity/ 自带，无需下载。
  • R2R 任务集：bash scripts/data/fetch_episodes_vln.sh --r2r → data/mp3d/tasks/R2R/R2R_{train,val_seen,val_unseen,test}.json。
  • MapGPT72 头条分割：R2R_MapGPT72.json（216 条 = 72 scene × 3 指令）与 R2R_MapGPT72_first.json（72 条）放进 data/mp3d/tasks/R2R/ 即被自动发现，split=MapGPT72 直接可用。

MapGPT 本身不需要任何预计算观测缓存或本地神经模型（NavGPT 才要 caption/object 缓存）—— 全程 MatterSim 实时渲染 + API 调用，唯一的"模型"就是 profile 背后那个 LLM。

4. 启动方式（按手上工具选）

4.1 Web 工作台：画布实况 / Eval 页批跑

conda activate agentcanvas
cd agentcanvas && bash run_dev.sh     # 后端 :8000 + 前端 :5173

# 加载两个 nodeset（UI 里点，或直接 curl）
curl -X POST http://localhost:8000/api/components/nodesets/mapgpt/load
curl -X POST 'http://localhost:8000/api/components/nodesets/env_mp3d/load?mode=server'

打开 http://localhost:5173：画布加载 mapgpt_mp3d 可单集实况跑（能看到每个节点的输入输出流动）；Eval 页选 split + episode 范围批跑，进度走 WebSocket，产物在 outputs/eval_runs/{run_id}/episodes/ep{NNNN}/。

4.2 HTTP API：脚本 / CI

curl -X POST http://localhost:8000/api/eval/v2/start \
  -H 'content-type: application/json' \
  -d '{"graph_name": "mapgpt_mp3d", "split": "MapGPT72", "worker_count": 4}'
# 轮询  GET /api/eval/v2/status     取回  GET /api/eval/v2/export/{run_id}

4.3 Claude Code 里：/experiment:run（带 GPU 准入）

/experiment:run smoke_mapgpt_mp3d mapgpt_mp3d              # 3 集冒烟
/experiment:run perf_mapgpt_mp3d mapgpt_mp3d split=MapGPT72 episode_count=216 worker_count=4

profile 在 .claude/commands/experiment/profiles.yaml；wrapper 经 JobScheduler 申请 VRAM、自动分配端口，配套 /experiment:status 与 /experiment:teardown。

4.4 独立批跑脚本（走交互 run API）

python scripts/eval/run_mapgpt_batch.py        # 从第 0 集起跑 20 集
python scripts/eval/run_mapgpt_batch.py 30 5   # 从第 5 集起跑 30 集
# 汇总写 outputs/mapgpt_batch_summary.csv

5. 口径与成本提示

  • 要可比数字用 MapGPT72：val_unseen 排序偏简单，取前缀会把 SR 高估约 18–22 个百分点。
  • 成本量级（216 集全量）：gpt-5-mini ≈ $5/run，gpt-4o ≈ $26/run。
  • 排查"图跑了但结果全是假的"：多半是 key 没配好、节点掉进了 mock 模式（见 §2 第 3 条）；后端启动时设 AGENTCANVAS_STRICT_ERRORS=1 可让 LLM/节点错误直接抛出。
  • 解释器路径同样注意 miniforge3 / miniconda3 差异，必要时设 MP3D_PYTHON。
