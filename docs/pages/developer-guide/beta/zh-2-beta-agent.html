跑通 Beta Coding Agent（中文）

让一个裸 Claude coding agent 通过 MCP 驱动 Habitat 跑 R2R-CE —— 从环境到出分的完整手册。

这套实验测的是：一个零具身特化的 Claude coding agent（Claude Agent SDK 会话）在 R2R-CE 导航上能得几分。agent 只看得到 observe()（第一人称 RGB）和 step(actions)（离散动作），拿不到位姿、深度、地图和分数 —— 选集、评测全在 driver 侧，用与 workspace/graphs/vln/verified/ 里的图完全相同的 env_habitat__evaluate 打分。系列文档：仓库概览 · 本篇 · MapGPT 流程 · Agent vs Coding Agent；英文监控页文档见 Coding-Agent Monitor。

1. 双进程结构：谁连着谁

┌─ 进程 A（conda: ac-vlnce, Python 3.8）────────────────┐
│  auto_host :9200 → env_habitat nodeset → Habitat-Sim  │
└──────────────────────── ▲ HTTP /call/{fn} ────────────┘
                          │
┌─ 进程 B（conda: agentcanvas）─────────────────────────┐
│  run_episodes.py（driver，选集/评测/记录）             │
│    └─ claude-agent-sdk → 生成 claude CLI 无头会话      │
│         └─ mcp_bridge.py（stdio MCP 子进程，每集一个） │
│              工具：observe / step / look_around        │
└───────────────────────────────────────────────────────┘
文件角色
beta-coding-agent/mcp_bridge.pystdio MCP server（FastMCP("habitat-env")）；把工具调用转发为对 auto_host 的 POST /call/{fn}。每个 agent 会话（= 每集）一个 bridge 进程。
beta-coding-agent/run_episodes.pyDriver：经 /env-panel/* 放置 episode，每集起一个干净 SDK 会话，会后调 env_habitat__evaluate，写 outputs/beta-coding-agent/{run}/。
beta-coding-agent/skills/*/SKILL.md三个导航策略 skill（纯 prompt，见 §5），按 --skill 目录名 追加进 system prompt。
beta-coding-agent/opus-lab/洁净房变体：固定环境、只变 skill 的爬山实验（见 §7）。

Agent 看到的 MCP 工具（SDK 侧 server key 为 env）：

工具作用
mcp__env__observe第一人称 RGB（base64 PNG）。非 bare 模式附带 JSON 状态：clearance_m（深度导出的左/中/右净空米数）与回合预算字段。纯读取，不推进模拟。
mcp__env__stepactions: list[int]，0=STOP，1=前进0.25m，2=左转15°，3=右转15°，单次最多 50 个。返回执行数、总步数、剩余预算、episode_over 等。非 bare 模式有 STOP 确认门（预算充裕时第一次 step([0]) 会被扣下要求确认）。
mcp__env__look_around前/右/后/左四视图，旋转一周后恢复朝向，消耗 24 步转向预算。仅非 bare 模式注册。

STOP 必须由 agent 自己发出。成功判定要求在目标 3 m 内主动 STOP；driver 永不强停 —— 不停的 agent 会诚实地以预算耗尽时的 distance-to-goal 计分。

2. Claude SDK 怎么接的（以及认证的坑）

  • 机制：Python 包 claude-agent-sdk（ClaudeSDKClient + ClaudeAgentOptions），底层由 SDK 生成无头 claude CLI 进程。不是裸 Anthropic API，也不是手工 shell 调 CLI。
  • 认证走订阅：先在本机 claude 登录一次即可。driver 会主动剥掉继承到的 ANTHROPIC_API_KEY —— 无头模式下这个变量会把计费悄悄切到 API。保险起见照 opus-lab 的习惯用 env -u ANTHROPIC_API_KEY python … 启动。
  • 会话约束：tools=[]（无 Bash/文件系统等内置工具，纯 ReAct 对环境）、allowed_tools 锁定为上表 2–3 个 MCP 工具、strict_mcp_config=True、permission_mode="bypassPermissions"。
  • 模型选择：--model 直传 SDK（如 claude-fable-5、claude-opus-4-8）；缺省用账号默认。thinking 配置按模型族自动选：4.6+/5 系走 adaptive，haiku 系用 --think-budget（默认 4000）指定预算；返回的 thinking 一律是摘要而非原文。--betas 可透传 beta 头（如 interleaved-thinking-2025-05-14）。

3. 前置检查（数据就绪即可跑）

  • conda 环境 agentcanvas（driver）与 ac-vlnce（Habitat，Py3.8；由 bash scripts/install/install_ac_vlnce.sh 创建）都已装好。
  • 数据就位：R2R-CE episodes + MP3D 场景等，bash scripts/data/fetch_data_vlnce.sh --status 查看缺什么。
  • claude CLI 已登录（订阅认证）。
  • 端口 9200 空闲（选它是因为避开 JobScheduler 池 8765–8769 和用户后端 :8000）。

解释器路径 仓库 README 写的是 ~/miniforge3/envs/…；用 miniconda3 的机器请替换为 $(conda info --base)/envs/…，或设 VLNCE_PYTHON 指向 ac-vlnce 的 python。

4. 两步跑起来

第 1 步 —— 起 Habitat auto_host（长驻前台进程，留着别关；AGENTCANVAS_EXECUTOR_URL 保持不设，事件推送即为空操作）：

REPO=$(git rev-parse --show-toplevel)
cd "$REPO/agentcanvas/backend"
PYTHONPATH="$REPO/agentcanvas/backend:$REPO" \
  "$(conda info --base)/envs/ac-vlnce/bin/python" -m app.server.auto_host \
  --file "$REPO/workspace/nodesets/env/env_habitat.py" \
  --class EnvHabitatNodeSet --port 9200

第 2 步 —— 驱动 episodes（另开终端；driver 起跑前会 GET /health 健康检查）：

conda activate agentcanvas
cd "$REPO"

# 单集冒烟
env -u ANTHROPIC_API_KEY python beta-coding-agent/run_episodes.py \
  --episodes 0 --split rand100

# 10 集校准 + 指定模型
env -u ANTHROPIC_API_KEY python beta-coding-agent/run_episodes.py \
  --episodes 0-9 --split rand100 --model claude-fable-5

# 挂一个导航 skill
env -u ANTHROPIC_API_KEY python beta-coding-agent/run_episodes.py \
  --episodes 0-9 --split rand100 --skill mapgpt-nav

# 纯 vanilla 基线（剥掉净空读数/预算广播/STOP 门/look_around）
env -u ANTHROPIC_API_KEY python beta-coding-agent/run_episodes.py \
  --episodes 0-9 --split rand100 --bare

# 并行：每个 auto_host URL 一个 worker（先在 :9201 再起一个第 1 步）
env -u ANTHROPIC_API_KEY python beta-coding-agent/run_episodes.py \
  --episodes 0-9 --server-urls http://127.0.0.1:9200,http://127.0.0.1:9201

rand100 是论文口径的 R2R-CE val_unseen 100 集子集（与 OpenNav/SmartWay 相同）。推荐节奏：1 集冒烟 → 10 集校准（token/延迟/订阅消耗）→ rand100。

4.1 CLI 参数全表（run_episodes.py）

参数默认说明

5. 三个导航 skill

skill思路
mapgpt-navMapGPT 式（arXiv 2401.07314）map-guided prompting：维护文本拓扑地图（Places），在图上做多步规划与回溯；每次回复固定五个记忆块（Trajectory / Map / Supplementary / Previous Planning / Progress）。
ledger-nav"像写代码一样导航"：由动作做航位推算（dead-reckoning），帧账本只索引不复制历史观测，predict→execute→verify 循环；依赖非 bare 模式的 clearance_m 等机制。
opus-nav给强模型的极简决策规则：route-verified grounding、先定向再提交、系统性回溯、果断落点；无记账。当前正被 opus-lab 爬山迭代。

6. Web 监控（Coding Agent tab）

起了主工作台（cd agentcanvas && bash run_dev.sh）后，前端顶栏有 Coding Agent tab：选 split（rand100 / val_unseen）、episode 范围、max_turns、可选模型，点 Run。后端会自己在空闲端口生成一个专属 auto_host 并以 --run-name ui_* 启动同一个 driver —— 与 CLI 产物同构，互相可浏览。REST 面（前缀 /api/coding-agent）：POST /start、POST /stop、GET /status、GET /runs、GET /runs/{run}/summary、GET /runs/{run}/episode/{i}/textlog?offset=N、…/frames、…/frame/{name}。

UI 只跑默认模式（单 worker、非 bare、无 skill）。要 --bare / --skill / --server-urls 并行 / --betas 等旋钮，走 CLI。v1 同时只允许一个 UI run。

CLI 跑时的三条实时观察通道（路径在 outputs/beta-coding-agent/{run}/ 下）：

# 1. agent 在想什么/做什么 —— 逐事件落盘的轨迹
tail -f outputs/beta-coding-agent/{run}/episode_{i}.jsonl | jq -r '"\(.t)s \(.kind)"'

# 2. agent 看到什么 —— live_{i}/ 里每帧 obs_*.png + 持续覆写的 latest.png
watch -n1 'tail -3 outputs/beta-coding-agent/{run}/live_{i}/actions.log'

# 3. 心跳 —— auto_host 终端的访问日志（observe/step 节律）

7. opus-lab 变体：固定环境，只变 skill

beta-coding-agent/opus-lab/ 是为 skill 爬山建的洁净房：观测永远是 RGB-D + 位姿/里程 + 相机内参（含 3×3 米制深度网格），look_around() 升级为 45° 间隔八视图且始终可用，顶层那些可调机制（预算广播、STOP 门、--bare 开关）一概不存在 —— 不带 --skill 就是纯基线。新增 --builtin-system-prompt：改用 CLI 内置 Claude Code preset system prompt，导航简报改为首条用户消息。skill 目录换成 opus-lab/skills/（现有 opus-nav）。

# 同样先起 :9200 的 auto_host（§4 第 1 步），然后：
env -u ANTHROPIC_API_KEY python beta-coding-agent/opus-lab/driver.py \
    --episodes 0-9 --skill opus-nav --model claude-opus-4-8

产物同样落在 outputs/beta-coding-agent/（run 名前缀 opuslab_），Monitor tab 可以浏览，但不能从 UI 启动 opus-lab（runner 硬编码顶层 driver）。

8. 产物与打分

outputs/beta-coding-agent/{run}/
├── summary.json            # 每集结果 + 运行级聚合（SR/SPL/…），含全部配置
├── episode_{i}.jsonl       # 精选轨迹（逐事件 flush，监控页实时 tail 的就是它）
├── raw/episode_{i}.jsonl   # 完整 SDK dump（--no-raw-log 可关）
└── live_{i}/               # 旁观帧：obs_*.png、latest.png、actions.log

指标出自 Habitat 自带 measure（经 env_habitat__evaluate）：SR、SPL、Oracle SR、nDTW、distance-to-goal 等 —— 与图方法完全同尺。10 集校准的早期数字与失败类型学见英文页 Coding-Agent Monitor §5。
