新环境从零跑通 Beta Coding Agent（中文）

全新机器 → 第一集出分的完整清单，以及 Claude Opus 驱动 VLN-CE 时到底发生了什么。

本页假设你拿到一台全新的 Linux 机器（有 NVIDIA GPU），目标是跑通 beta-coding-agent/：让订阅计划自带的 Claude 模型（如 claude-opus-4-8）通过 MCP 驱动 Habitat 完成 R2R-CE 导航并出分。§2 是照抄可用的准备清单（每一步都在真机上验证过）；§3 拆解跑一集时的完整调用链；§4 把 Claude Code 这个闭源 harness 分成"外部可见"和"只能推测"两半，讲清楚我们知道什么、不知道什么。系列前篇：仓库概览 · Beta Agent 运行手册。

1. 要凑齐的五样东西

组件作用来源

conda 环境 ac-vlnce（Py 3.8）跑 Habitat-Sim 0.1.7 模拟器（只能活在 3.8）scripts/install/install_ac_vlnce.sh
claude CLI + 订阅登录agent 本体；SDK 底层拉起它的无头会话claude.com/claude-code 安装，登录一次
Python 包 claude-agent-sdkdriver 与 claude CLI 之间的编程接口pip，装进 agentcanvas 环境

2. 从零清单（照抄可用）

2.1 平台与模拟器环境

# 前置：NVIDIA 驱动、conda（miniconda/miniforge 均可）、Node.js 18+
git clone https://github.com/jianzhou0420/AgentCanvas && cd AgentCanvas

# 主环境（后端 + driver）：按 docs-md/INSTALL.md 建 agentcanvas 环境
# 模拟器环境（Habitat，Py3.8）：
bash scripts/install/install_ac_vlnce.sh
# 结束时的 Step 6 verify 应显示 PyTorch / habitat-sim / habitat / vlnce_baselines 全 OK

2.2 Claude 侧

# claude CLI 装好后登录一次（订阅认证，之后无头会话共用这份凭据）
claude   # 首次进入会走 OAuth 登录

# SDK 装进 agentcanvas 环境
"$(conda info --base)/envs/agentcanvas/bin/pip" install claude-agent-sdk

计费大坑 无头模式下只要环境里有 ANTHROPIC_API_KEY，计费就会悄悄从订阅切到 API。driver 会自动剥掉它，但习惯上所有启动命令都带 env -u ANTHROPIC_API_KEY 双保险。

2.3 数据下载与归位

bash scripts/data/fetch_data_vlnce.sh --r2r    # R2R-CE episodes（约 250MB）
bash scripts/data/fetch_data_vlnce.sh --mp3d   # MP3D 场景（约 21GB）
# beta agent 不需要 --ddppo / --checkpoints（那是图方法/policy 用的）

# 确认落点是 data/habitat/（老版本脚本有路径 bug 会落到 scripts/data/habitat/，
# 遇到就整体 mv 过去）：
ls data/habitat/   # 应有 datasets/ scene_datasets/

# 补软链（install 脚本在数据缺失时会跳过这步）：
cd third_party/VLN-CE/data
ln -s ../../../data/habitat/datasets datasets
ln -s ../../../data/habitat/scene_datasets scene_datasets
cd -

2.4 重建 rand100 分割

论文口径的 100 集子集 rand100不在标准 VLN-CE 数据包里。它与 Open-Nav（ICRA 2025，YanyuanQiao/Open-Nav）/ SmartWay 的官方评测子集完全一致，做法是拿 Open-Nav 发布的 episode 列表过滤本地 v1-3 val_unseen：

# 1) 下 Open-Nav 官方 100 集文件（Google Drive ID 来自其 README；文件虽名 .gz 实为纯 JSON）
"$(conda info --base)/envs/ac-vlnce/bin/python" -m gdown \
    1SfrPWqCIiivwduCYPMe-Za1wOt4eU6G9 -O /tmp/opennav_100.json

# 2) 过滤生成 rand100/{rand100.json.gz, rand100_gt.json.gz}
"$(conda info --base)/envs/agentcanvas/bin/python" - <<'EOF'
import gzip, json, os
ids = {ep['episode_id'] for ep in json.load(open('/tmp/opennav_100.json'))['episodes']}
base = 'data/habitat/datasets/R2R_VLNCE_v1-3_preprocessed'
vu = json.load(gzip.open(f'{base}/val_unseen/val_unseen.json.gz'))
sub = [ep for ep in vu['episodes'] if ep['episode_id'] in ids]
gt = json.load(gzip.open(f'{base}/val_unseen/val_unseen_gt.json.gz'))
gtsub = {k: v for k, v in gt.items() if int(k) in ids}
assert len(sub) == 100 and len(gtsub) == 100
os.makedirs(f'{base}/rand100', exist_ok=True)
json.dump({'episodes': sub, 'instruction_vocab': vu['instruction_vocab']},
          gzip.open(f'{base}/rand100/rand100.json.gz', 'wt'))
json.dump(gtsub, gzip.open(f'{base}/rand100/rand100_gt.json.gz', 'wt'))
EOF

2.5 起模拟器、跑第一集

# 终端 A：Habitat auto_host（长驻；health 秒回，场景在首次 play 时才冷加载）
REPO=$(git rev-parse --show-toplevel)
cd "$REPO/agentcanvas/backend"
PYTHONPATH="$REPO/agentcanvas/backend:$REPO" \
  "$(conda info --base)/envs/ac-vlnce/bin/python" -m app.server.auto_host \
  --file "$REPO/workspace/nodesets/env/env_habitat.py" \
  --class EnvHabitatNodeSet --port 9200
curl http://127.0.0.1:9200/health   # {"status":"ok",...}

# 终端 B：跑一集（用订阅自带的 Opus）
cd "$REPO"
env -u ANTHROPIC_API_KEY "$(conda info --base)/envs/agentcanvas/bin/python" \
  beta-coding-agent/run_episodes.py \
  --episodes 0 --split rand100 --model claude-opus-4-8

推荐节奏：单集冒烟 → --episodes 0-9 十集校准（估 token/时长/订阅额度消耗）→ rand100 全量。产物在 outputs/beta-coding-agent/{run}/（轨迹 JSONL、旁观帧、summary.json 聚合分），前端 :5173 的 Coding Agent tab 可实时/事后浏览。

3. 用 Opus 跑一集：完整调用链

run_episodes.py（driver，agentcanvas 环境）
 │ ① POST /env-panel/field/{dataset,split,episode_index}     ┐
 │ ② POST /env-panel/action/play（首次触发 MP3D 场景冷加载）  │ auto_host :9200
 │ ③ POST /call/env_habitat__reset → 拿到本集自然语言指令     │ （ac-vlnce 环境）
 │                                                           ┘
 │ ④ 组 system prompt（导航简报 + 指令 + 步数预算 [+ skill]）
 │ ⑤ ClaudeSDKClient 起会话
 │     └─ SDK 拉起无头 claude CLI（--model claude-opus-4-8）
 │         └─ CLI 拉起 mcp_bridge.py 子进程（stdio MCP）
 │              ├─ mcp__env__observe      → GET 第一人称 RGB（+净空读数）
 │              ├─ mcp__env__step([...])  → 执行 0/1/2/3 动作串
 │              └─ mcp__env__look_around  → 四向环视（非 bare 模式）
 │     Opus 循环：observe → 思考（adaptive thinking）→ step → …… → step([0]) STOP
 │ ⑥ 会话结束（STOP / 回合耗尽 / 超时）
 │ ⑦ POST /call/env_habitat__evaluate → SR / SPL / nDTW / dist-to-goal
 └ ⑧ 写 episode_{i}.jsonl + raw dump + summary.json，进入下一集

要点：每集一个全新会话（无跨集记忆），episode 选择与打分全在 driver 侧，Opus 只见得到指令文本和 RGB 图，见不到位姿/地图/分数；0=STOP，1=前进0.25m，2=左转15°，3=右转15°，成功要求在目标 3 m 内自己发 STOP。claude-opus-4-8 属 4.6+ 系，driver 自动给它配 adaptive thinking（返回的思考内容是摘要，不是原始链）。订阅额度按会话消耗——rand100 全量跑之前先用十集校准估计消耗。

4. Claude Code harness：可见的与闭源的

agent 本体是 Claude Code 的无头模式，harness 闭源。但"闭源"不等于黑箱——下面按证据强度分两层。

4.1 外部可直接观察的组件

组件怎么看到
claude-agent-sdk（Python，开源）pip 装的包，源码可读：ClaudeSDKClient / ClaudeAgentOptions、消息类型（AssistantMessage、ToolUseBlock、ThinkingBlock、ResultMessage…）。它本质是 claude CLI 的进程包装器 + JSON 流解析器。
CLI 无头协议SDK 以 stream-JSON 与 CLI 通信；raw/episode_{i}.jsonl（driver 默认开）记录了每一条：会话 init（session_id、工具清单、模型、权限模式）、每轮 assistant 消息、逐轮 token 用量（input/output/cache_read/cache_creation）、末尾 ResultMessage（总用量、总时长、回合数）。
MCP（开放标准）stdio 上的 JSON-RPC：tools/list、tools/call；工具名按 mcp__{server}__{tool} 规则拼出。bridge 是本仓库代码，两边报文都能 log。
我们传入的全部旋钮ClaudeAgentOptions 里明码写着：model、system_prompt（本实验整体替换了 Claude Code 默认 preset；opus-lab 的 --builtin-system-prompt 可切回 preset+首条消息模式）、tools=[]（禁用全部内置工具）、allowed_tools（白名单三个 MCP 工具）、permission_mode="bypassPermissions"、strict_mcp_config、max_turns、thinking 配置、beta 头。
认证与计费面订阅 OAuth 凭据在 ~/.claude/；有 ANTHROPIC_API_KEY 时切 API 计费（可观察到的行为差异）。

4.2 闭源部分可能包括什么（标注：合理推测）

推测的内部机制依据
CLI 自带的 system prompt preset（工具使用纪律、agent 循环规范、输出风格）——被本实验替换掉的那份官方文档承认 preset 存在且可替换/追加；具体文本不公开
长会话的上下文管理：自动压缩/摘要（compaction）、工具结果截断策略长会话不会无限膨胀、CLI 有 /compact 概念；阈值与摘要算法不可见
Prompt caching 的断点安排（system prompt / 工具 schema 处打 cache 点）raw 日志里每轮可见大量 cache_read_input_tokens，但断点策略是 CLI 内部行为
思考摘要化：原始 thinking 在服务端/CLI 被压成摘要再吐给 SDK4.6+/5 系只返回 summarized thinking，这是可观察的输出约束，实现不可见
重试/限流/断线恢复、采样参数（temperature 等未暴露）、图片预处理（分辨率压缩）SDK 不暴露这些旋钮；行为上偶见自动重试的时间特征
权限系统内部实现、遥测上报、会话持久化格式permission_mode 只是开关；~/.claude/ 下有会话文件但格式无文档

对实验的意义 "vanilla coding agent" 的分数里其实叠着这些闭源 scaffolding 的贡献（上下文压缩、工具循环纪律、缓存带来的长会话可行性）。所以对照组才重要：--bare 剥环境侧机制、--builtin-system-prompt 切换提示词来源、--skill 只动策略层——环境和 harness 不变，动一层测一层。

5. 常见故障速查

症状原因 / 处理
UI 点 Run 报 "Server did not become healthy within 1800s"数据没就位（habitat 加载不了 episodes/场景）。按 §2.3–2.4 补数据
driver 报找不到 rand100rand100/ 没建。按 §2.4 重建，或先用 --split val_unseen
import claude_agent_sdk 失败SDK 装错环境。装进 agentcanvas（driver 用的解释器）
跑着跑着扣 API 账单环境里有 ANTHROPIC_API_KEY。env -u ANTHROPIC_API_KEY 重跑
GL::Context / EGL 报错conda 的 GL 库和系统 NVIDIA 驱动打架；install 脚本 Step 3 会删 conda GL 库，重跑安装或手动 conda remove libgl libglvnd libglx libegl --force
agent 一直不 STOP，分数按 dist-to-goal 结算预期行为（driver 永不强停）。这正是 vanilla 基线要测的东西之一
