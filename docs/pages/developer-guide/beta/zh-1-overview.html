AgentCanvas 仓库概览（中文）

这个仓库是干什么的、代码放在哪、怎么跑起来 —— 一页速览。

AgentCanvas 是一个具身智能体（Embodied Agent）的可视化图式设计平台：把一个 VLN / EQA / VLA 智能体画成节点连线图（node graph），实时跑在真实模拟器（Habitat-Sim、MatterSim、SAPIEN/ManiSkill2、MuJoCo/robosuite）上。核心原则是 one JSON = one agent：智能体的全部行为 —— 节点、连线、配置、状态容器、hook —— 就是一个 JSON 文件，加载即运行。同一套图基座扮演两个角色：给人用的运行基座（harness），和给 coding agent 改的搜索脚手架（scaffold）。

本页是四篇中文速览的第一篇。后三篇：跑 Beta Coding Agent（Claude SDK 接入） · 用普通大模型跑 MapGPT · 普通 Agent vs Coding Agent（概念对比）。英文正式文档见左侧导航。

1. 它解决什么问题

现代具身智能体不是一个模型，而是一整个系统：LLM 推理 + 工具调用 + 模拟器耦合 + 空间工具。每篇论文各写一套代码，导致几类老毛病：

  • 执行层成本压倒想法本身 —— 大部分工程量花在跑通模拟器和模型栈，而不是要验证的方法上。
  • 隐藏的 ground-truth 依赖 —— 很多方法悄悄用了模拟器给的真值（物体位姿、语义标签、可导航性），论文里不提。
  • 不可复现 —— 代码"coming soon"，或者论文流程图和实际实现对不上。
  • 强耦合 —— prompt / 工具 / 策略和基础设施缠在一起，换一个组件等于重写管线。

AgentCanvas 的答案：把方法拆成类型化的图。方法逻辑是 method 节点、模拟器是 env 节点、模型是 model 节点、策略是 policy 节点，四个 palette 共 40+ nodeset，互相可替换；图本身可 diff、可分享、可被 coding agent 自动搜索（AAS）。

2. 三个核心概念

概念一句话落点
Graph（图）一个 JSON = 一个智能体；画布上看到什么就执行什么。支持 DAG、observe-think-act 循环（IterIn/IterOut 双支点）、多作用域迭代、有界多智能体。workspace/graphs/（已验证的 VLN 图在 vln/verified/）
Nodeset（节点集）一个 Python 类 = 一个节点：声明端口、实现 forward()，丢进 workspace/ 即被自动发现，无需注册。workspace/nodesets/{env,method,model,policy}/
Server mode（服务模式）重依赖的 nodeset（如 Habitat 只能跑 Python 3.8）作为子进程跑在自己的 conda 环境里，通过 HTTP（auto_host）被图调用 —— 同一份节点代码，两种部署方式。agentcanvas/backend/app/server/auto_host.py

另有状态容器（StateContainer）：画布上可见的命名记忆体，带 reducer（Accumulator / LastWrite / Counter）和生命周期轴（step / episode / run / forever），到边界自动清空 —— MapGPT 的拓扑地图、历史、规划就放在这里。

平台主体跑在默认 agentcanvas 环境（Python 3.10+）；每个重模拟器有自己的隔离环境，以 server mode 子进程接入：

conda 环境承载典型消费者解释器覆写变量

ac-mp3dMatterSim 离散全景环境 env_mp3dMapGPT / NavGPT 等 MP3D 图MP3D_PYTHON
ac-smartwaySmartWay 系（Habitat CE）专属依赖smartway_ce 图—

路径提醒 仓库文档里的示例常写 ~/miniforge3/envs/…；本机若用 miniconda3，请替换为 $(conda info --base)/envs/…，或直接设置上表的解释器覆写变量。

6. AAS：让 coding agent 搜索架构

在"手画图 + 评测"之上，AgentCanvas 是 Agent Architecture Search 的基座：LLM coding-agent 作为 Optimizer，反复对种子图（iter_0 = 一个已发表方法）提出图级修改、下模拟器评测、留下有效改进。因为智能体就是类型化的图，每个候选先过类型检查再进昂贵的 rollout，逐节点日志让 Optimizer 能把分数变化归因到具体模块。三种搜索策略以 Claude Code 技能形式放在 .claude/commands/architect/：

技能论文名搜索策略
myloopKDLoopTHINK → CRITIC → EXPERIMENT → DISTILL 四相循环 + 类型化记忆 + REFLECT 元相
adas-subagentADAS（移植）Reflexion 式提案 + 扁平追加档案
aflowAFlow（移植）分数 softmax 选父 + 防重放记忆
 
# 在本仓库的 Claude Code 会话里，对 MapGPT 执行器跑 KDLoop
/architect:myloop:loop mapgpt_mp3d --goal "raise val_unseen SR"

已接好的种子图：mapgpt_mp3d、smartway_ce（VLN）、explore_eqa_hmeqa（EQA）、voxposer_libero_monolithic（VLA）。每轮迭代产物在 outputs/design_runs/{variant}/{graph}/vN/iter_M/。

7. 本分支（dev/coding-agent）新增了什么

这个分支是 "AgentCanvas 2.0 的种子实验"：不画图，直接让一个裸 Claude coding agent通过 MCP 驱动 env_habitat 跑 R2R-CE，量一量零具身特化的 coding agent 能得几分 —— 用和已验证图完全相同的 env_habitat__evaluate 尺子。新增三块：

  • beta-coding-agent/ —— MCP bridge + episode driver + 三个导航 skill + opus-lab/ 洁净房变体；
  • 后端 /api/coding-agent/* + 前端 Coding Agent 监控 tab（一键起跑、实时轨迹 + 帧回放）；
  • 本 Beta 文档区（英文的 Coding-Agent Monitor 页 + 这三篇中文速览）。

怎么跑、怎么接 Claude SDK，见第二篇：跑 Beta Coding Agent。
